# Development Standards

## 命名

仓库、数据目录和输出目录使用小写英文语义名称。Python 代码遵循 PEP 8：包、模块、函数和变量用 `snake_case`，类用 `PascalCase`，常量用 `UPPER_SNAKE_CASE`。这是对通用驼峰规范的语言级例外，避免破坏 Python 生态工具与导入约定。

## 设计与实现

- 文件系统路径只在 `config.py` 定义，算法模块不得硬编码本机绝对路径。
- 公共函数提供 docstring；异常信息要能说明失败对象和补救方向。
- 使用 `logging` 记录阶段、输入、输出和错误；不记录凭据与敏感数据内容。
- 新增第三方依赖前记录用途、许可证、版本范围和维护风险。
- 设计变化同步更新架构、数据契约和风险登记。

## 测试与审查

- 核心纯函数必须有单元测试；文件流水线至少提供一条烟雾测试。
- 目标单元测试覆盖率不低于 80%；未达到时不得写成“已符合”，必须登记差距与补测计划。
- 合并前运行静态检查和测试，由非代码作者完成审查。
- 发布前核对许可证、数据再分发权、依赖安全和回滚方式。
