# GitHub Release Checklist

## 代码发布前必须完成

- [ ] 在 `CITATION.cff` 填写真实作者、仓库 URL；有 DOI 后补 DOI。
- [ ] 在 `SECURITY.md` 配置可用的私密报告渠道。
- [ ] 在 GitHub 创建仓库并确认默认分支，启用分支保护、至少一人审查和 CI 必须通过。
- [ ] 首次远程 CI 在 Python 3.10 和 3.11 上通过。
- [ ] 运行依赖漏洞、许可证和密钥扫描，复核生成的传递依赖清单。
- [ ] 创建带版本号的 release 分支或 tag，并记录回滚目标。

## 若要同时发布数据或模型，必须额外完成

- [ ] 为每个数据来源补齐名称、版本、URL/提供单位、获取日期和再分发许可。
- [ ] 提供标注规范、质量控制、偏差、脱敏和固定划分清单。
- [ ] 为模型提供 model card、训练数据范围、指标边界、权重校验值和独立许可。
- [ ] 确认论文、图片、表格和第三方标注不受保密、竞赛或出版协议限制。

在这些项目完成前，保持 `data/`、`models/` 和 `artifacts/` 的现有 Git 忽略规则。
